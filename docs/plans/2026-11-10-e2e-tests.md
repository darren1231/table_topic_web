# 實作計畫：瀏覽器整合測試（E2E）

- 日期：2026-11-10
- 分工：Claude 負責規劃與 review，Codex 負責實作
- 目標：用真的瀏覽器自動跑過使用者常用的流程，每個 PR 由 GitHub Actions 自動執行，減少人工測試。
- 範圍：只新增測試與測試基礎設施，**不修改 `public/` 的網站行為**。發現 bug 時不修，用 `test.fixme` 或註解 `// KNOWN ISSUE:` 記錄並回報。

## 固定規格

- 工具：`@playwright/test`，**固定版本 `1.64.1`**（2026-10-14 發布）。使用 `--save-exact`。不得新增其他 devDependency。
- 目錄：`e2e/`，設定檔 `playwright.config.cjs`。
- 網站伺服器：新增 `scripts/serve-public.mjs`，只用 Node 內建模組，從 `public/` 提供檔案，行為比照 Vercel：
  - `cleanUrls`：`/admin` 對應 `public/admin.html`。
  - 不存在的路徑回傳 404。
  - 只綁 `127.0.0.1`。
  - 由 Playwright 的 `webServer` 啟動。
- 瀏覽器專案：
  - `chromium`：Desktop Chrome。
  - `webkit-iphone`：WebKit，使用 Playwright 內建的 iPhone 裝置設定。
- 網路隔離：每個測試預設**攔截所有不是 `127.0.0.1` 的請求**。
  - `*.supabase.co`：由測試 fixture 模擬。
  - `/api/**`：由測試 fixture 模擬。
  - Supabase SDK 的 CDN（`cdn.jsdelivr.net`）：允許載入，或改由 fixture 回傳本機檔案，二選一並在 README 說明。
  - 其他外部網址一律回傳錯誤，並讓測試失敗。
  - 絕對不可以連到真正的 OpenAI 或 Supabase 專案。
- 時間：需要固定日期的測試用 `page.clock`。
- 指令：
  - `npm run e2e`：跑全部瀏覽器整合測試。
  - `npm test` 維持只跑單元測試，不包含 e2e。
- 測試內不得出現真實的 email、key 或 token；假的 email 一律使用 `@example.invalid`。
- 通用檢查：每個流程結束時，確認畫面可見文字中沒有 `&amp;`、`&lt;`、`&quot;`、`&#39;` 等未解碼的實體，也沒有 console error（已知且合理的錯誤除外，需列出原因）。

## 步驟

一次只做一個步驟。每步一個 commit，完成後回報「E? DONE」並停下來等 review。commit message 用英文，最後加一行 `Co-Authored-By: Codex <noreply@openai.com>`。不要 push。

### E1：基礎設施

- 安裝 Playwright 1.64.1，加入 `playwright.config.cjs` 與 `scripts/serve-public.mjs`。
- `e2e/fixtures.cjs`：
  - 網路隔離。
  - `guestPage`：未登入、localStorage 乾淨。
  - `signedInPage`：用假的 Supabase session 與模擬的 auth、rpc 端點，讓 `cloud.js` 認為已登入。
  - 模擬 `/api/ai/respond`、`/api/ai/transcribe`、`/api/ai/balance` 的工具函式，可以設定回傳內容與狀態碼。
- 一個冒煙測試：首頁可以載入、沒有 console error、兩個瀏覽器專案都通過。
- `.gitignore` 加入 `test-results/`、`playwright-report/`。

### E2：訪客流程

1. 內建教練：輸入主題 → 產生題目 → 輸入回答 → 分析 → 看到分數與回饋。
2. 歷史紀錄出現新的一筆 → 打開詳細報告。
3. 日曆與連續天數更新。
4. 從分析結果加入一張複習卡 → 複習頁面評分 → 卡片庫搜尋 → 批次封存。
5. 切換四種語言，確認主要標題與按鈕改變。阿拉伯語沒有 RTL 是已知問題，只記錄不修。
6. 匯出備份檔（攔截下載並檢查 JSON 格式），清空資料後再匯入，確認資料回來。

### E3：登入後與後台

1. 系統 AI：產生題目、分析回答，畫面顯示「已用 / 額度」並有更新。
2. 額度用完（402）：顯示提示並改用內建教練完成回饋。
3. 登入過期（401）：顯示重新登入提示。
4. `/admin`：
   - 管理員看到統計卡片、使用者表與明細，篩選可以運作。
   - 非管理員只看到「沒有權限」。
   - 未登入看到「請先登入」。

### E4：錄音（只在 chromium）

- 使用 Chromium 的假麥克風（`--use-fake-ui-for-media-stream`、`--use-fake-device-for-media-stream`）。
- API 轉錄模式：開始錄音 → 停止 → 模擬 `/api/ai/transcribe` 回傳文字 → 文字出現在作答區。
- 模擬頁面隱藏再顯示：畫面顯示「已保留 m:ss」，按繼續後可以接著錄，最後兩段文字依序出現。
- `webkit-iphone` 專案中標記為 skip，並註明原因（沒有假麥克風）。

### E5：CI 與文件

- `.github/workflows/test.yml` 新增獨立的 `e2e` job，與現有的 `test` job 平行執行：
  - `npm ci` → `npx playwright install --with-deps chromium webkit` → `npm run e2e`。
  - CI 中 `retries: 1`。
  - 失敗時用 `actions/upload-artifact` 上傳 `playwright-report/`（版本鎖定到明確號碼，並確認該版本存在）。
  - 權限維持 `contents: read`。
- README 新增「瀏覽器整合測試」段落：本機執行方式、模擬了什麼、測不到什麼（真實 Google 登入、真實 OpenAI、iPhone 實機錄音與螢幕鎖定、排版美觀）。

## 完成後

大部分 PR 只要 GitHub 的 `test` 與 `e2e` 兩個檢查都通過就能合併。只有改動登入、錄音或明顯的畫面調整時，才需要人工在 preview 網址確認。
